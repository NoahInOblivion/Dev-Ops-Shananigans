AUTOMATION & DEVSECOPS

Automated CI/CD & DevSecOps Security Gates

Shift-left quality and container vulnerability gates in GitHub Actions (.github/workflows/ci-cd.yml)

Quality Gate: Automated Pytest Suite
  • Executes on every Git push prior to container image creation
  • Validates task creation, status advancement, and statistics calculations
  • Uses isolated SQLite mock database to prevent test pollution
  • Fail-Fast Behavior: Broken tests halt pipeline immediately before resource consumption
Security Gate: Trivy Vulnerability Scan
  • Performs automated CVE scans on backend and frontend images
  • Configured to flag and break pipeline on HIGH or CRITICAL findings
  • Scans OS packages and application dependencies
  • Written CVE analysis documents all evaluated vulnerabilities
Artifact Publishing: Immutable SHA Tags
  • Images tagged with exact Git commit hash ${{ github.sha }}
  • Eliminates ambiguity caused by the mutable latest tag
  • Pushed directly to GitHub Container Registry (GHCR)
  • Guarantees 100% reproducible deployments and effortless rollbacks
Verification: Ephemeral Kind Cluster
  • Spins up a throwaway Kubernetes cluster within GitHub Actions runner
  • Loads newly-built SHA images and applies manifests
  • Awaits condition kubectl wait --for=condition=ready
  • Executes live in-cluster HTTP smoke tests against endpoints

Kubernetes Workloads & Helm Packaging

Production-ready Helm packaging, Ingress networking, and autonomous autoscaling

Helm Packaging (helm/taskboard)
  • Clean chart structure: Chart.yaml, values.yaml, and templates

INCIDENT RESPONSE & TROUBLESHOOTING

Production Troubleshooting Challenge

Simulated root cause analysis and resolution workflows on broken Kubernetes resources

Challenge 1: ImagePullBackOff Incident
  • Symptom: Pod stuck in ErrImagePull / ImagePullBackOff state.
  • Root Cause Analysis: Executed kubectl describe pod. Identified that the deployment referenced an invalid, non-existent registry tag: example.invalid/taskboard:nonexistent-tag.
  • Remediation: Patched container image directly using:
    kubectl set image deployment/broken-image app=nginx:1.25-alpine
  • Verification: Pod successfully pulled image and transitioned to Running (1/1).
Challenge 2: Service Selector Misconfiguration
  • Symptom: Ingress returning HTTP 503; kubectl get endpoints broken-service returned <none>.
  • Root Cause Analysis: Compared Service selector labels (app: misconfigured-label) against target Pod labels (app: broken-image). Discovered label mismatch.
  • Remediation: Patched the Service selector to match active pod labels using:
    kubectl patch service broken-service -p '{"spec":{"selector":{"app":"broken-image"}}}'
  • Verification: Endpoints immediately populated with pod IP:port; traffic successfully restored.
